Quadlets

native container orchestration with systemd

a 15-minute lightning talk

The Frankenstein Stack

We love containers. Managing them on bare metal is messy. K8s is a beast

  • docker compose - awkward, needs docker
  • podman generate systemd - deprecated, clunky, huge output
  • cron + docker run - there must be a better way

What if your init system was your orchestrator?

What is a Quadlet?

A specialized systemd unit file that systemd natively understands as a container.

  • .container: defines a container
  • .volume: persistent storage
  • .network: a bridge network
  • .kube: a Kubernetes YAML file (if you must)

The declarative bridge between systemd and the Podman runtime.

Why Quadlets Win

  • Native integration — no wrapper scripts; systemd is the manager
  • Dependencies — After=, Requires=, Wants=
  • Rootless — systemd --user + lingering, no root daemon
  • Or rootfull — systemd picks up /etc/containers/systemd/* on daemon-reload
  • Auto-updates — AutoUpdate=registry
  • INI syntax — no YAML indentation, no Python wrappers

Anatomy of a Quadlet

Four familiar systemd sections.


[Unit]
Description=Demo Nginx Server

[Container]
Image=docker.io/library/nginx:alpine
PublishPort=8080:80
Volume=web-data.volume:/usr/share/nginx/html

[Service]
Restart=on-failure

[Install]
WantedBy=default.target

Demo: Two Files, Zero Scripts

Drop these in ~/.config/containers/systemd/

webserver.container

[Container]
Image=docker.io/library/nginx:alpine
PublishPort=8080:80
Volume=web-data.volume:/usr/share/nginx/html

[Install]
WantedBy=default.target
web-data.volume

[Volume]
Label=purpose=demo

Demo: Bring It Up


# generate systemd units from the quadlet files
systemctl --user daemon-reload

# start the service
systemctl --user start webserver.service

# in a second terminal — watch it live
journalctl --user -u webserver.service -f

Then, from the first terminal:


systemctl --user restart webserver.service

Demo: The Payoff


podman exec webserver \
  sh -c "echo 'Hello from Quadlet' > /usr/share/nginx/html/index.html"

curl localhost:8080

Now restart the service. Curl again.

The file persists — Quadlet created and attached the volume for us.

Conclusion

No podman volume create.
No -v flags.
No shell script.
Just declare what is needed, and systemd makes it real.

Advanced Wizardry

  • .network — isolated bridge networks via systemd
  • .kube — run Kubernetes YAML directly through systemd
  • Templating — web@.service runs N instances
  • AutoUpdate=registry — self-updating containers

Gotchas

  • well, systemd. But it's there anyway so might as well embrace it
  • journalctl is a strange best friend to acquire
  • SELinux volume mounts may need :Z
  • Needs Podman 4.4+
